# Полноэкранный интерфейс персонажа и эталонный PDF

Дата: 2026-09-07

## Цель

Сделать создание, просмотр и повышение уровня персонажа плотными desktop-first рабочими экранами без пустующих боковых полей. Печатный лист остаётся отдельным светлым представлением и на данных контрольного персонажа воспроизводит предоставленный четырёхстраничный PDF с геометрическим допуском не более 3 px.

Референс полноэкранного мастера: `https://dnd24.charbox.org/`. Используются его принципы компоновки — постоянные шаги, карточная сетка, внутренний скролл и закреплённые действия. Брендинг, тексты и визуальные активы не копируются.

## Архитектурные решения

### Печатный лист

- Источник данных — `GET /characters/{id}/sheet`; правила 5e остаются на backend.
- `buildSheetModel` остаётся чистой границей между API и представлением.
- Экран, мобильный режим и печать используют один DOM.
- Геометрия задаётся для четырёх страниц A4. В тестовой системе координат одна страница — 795 × 1123 px при 96 DPI.
- Версия Chromium и набор локальных шрифтов фиксируются в CI.
- Контрольный LSS JSON нормализуется в API-фикстуру. Внешняя схема LSS не становится публичным контрактом приложения.
- В репозитории хранятся растеризованные страницы эталона, их SHA-256 и происхождение. Исходный PDF нужен только для воспроизводимой подготовки эталонов.
- Visual gate использует геометрическую метрику: каждому значимому пикселю контура должна соответствовать точка второго изображения в радиусе 3 px. Отдельный порог контролирует долю несовпавших пикселей и не позволяет скрыть пропущенный блок общим допуском.

### Мастер создания

- Общий `CharacterWorkspaceShell`: заголовок, постоянная левая колонка шагов, основная область с внутренним скроллом, закреплённая нижняя панель действий.
- На desktop карточки классов, рас и предысторий располагаются до четырёх в строке.
- Состояние выбора сохраняется при переходе на любой уже открытый шаг.
- На финальном шаге каждый раздел показывается отдельной карточкой с переходом к его редактированию.
- На узких экранах колонка шагов превращается в компактный индикатор. Desktop является первым приоритетом, но горизонтальный overflow запрещён.

### Интерактивный лист

- Ограничение ширины снимается; основной экран строится на 12-колоночной сетке.
- В первом viewport находятся идентичность, уровень и опыт, характеристики, здоровье, защита, скорость, спасброски и навыки.
- Заклинания, инвентарь, история и заметки используют всю доступную ширину в собственных областях.
- Печатный маршрут не зависит от компоновки интерактивного листа.

### Повышение уровня

- Backend предоставляет preview следующего уровня с перечнем затронутых областей и обязательностью выбора.
- Лист переходит в режим прокачки и подсвечивает именно те карточки, где доступно изменение: здоровье, характеристики или черта, подкласс, умения, заклинания и ячейки.
- Выбор делается в контексте карточки. Необязательное можно пропустить; обязательное блокирует подтверждение.
- Итог применяется одной транзакцией и создаёт одну запись истории. Частично повышенный уровень не хранится.
- Поддерживаются два явных режима: XP и ручное повышение. Ручной режим не подделывает значение XP.

## Нарезка реализации

1. DND-159 — контрольные данные Златобрада, точная печатная геометрия и обязательный visual gate.
2. Полноэкранная оболочка и мастер создания.
3. Широкий интерактивный лист.
4. Preview и контекстное повышение уровня.

Каждый следующий этап получает отдельную задачу и PR после стабилизации предыдущего контракта.

## Ошибки и отказоустойчивость

- Печать запрещается при переполнении любого контролируемого блока и показывает пользователю конкретную страницу и секцию.
- Отсутствующая карточка предмета или заклинания использует существующий локализованный fallback.
- Повторное подтверждение повышения уровня должно быть идемпотентным на уровне пользовательского действия; конкурентные запросы не могут поднять один исходный уровень дважды.
- Чужой персонаж во всех новых read/write сценариях возвращает 404 через существующую ownership-проверку.

## Проверки

- Unit: нормализация данных, модель листа, preview повышения и валидация обязательных выборов.
- Component: навигация мастера, сохранение выбора, подсветка доступных улучшений.
- Playwright: desktop 1440 × 900 без прокрутки документа, 1280 × 720, адаптивный режим 375 px, клавиатурная навигация.
- PDF: четыре страницы A4, размер растра 795 × 1123, геометрический допуск 3 px, отсутствие интерактивных контролов и обрезки.
- Backend: ownership, XP/manual режимы, атомарность, повторный и конкурентный запрос.

## Definition of Done

- Все строки проходят через i18next, а цвета — через токены темы.
- Бизнес-правила D&D не дублируются во frontend.
- CI блокирует структурную или геометрическую регрессию PDF.
- Изменённые текстовые файлы сохраняют CRLF и исходное состояние BOM.
- Реализация, тесты, backlog и описание PR согласованы между собой.
