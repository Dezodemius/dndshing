# Code style проекта

## Python (backend)
- Слои строго: router → service → models/schemas. Роутер: только парсинг входа, вызов одного сервис-метода, возврат схемы. Бизнес-логика и проверки владения — в сервисе. Запросы к БД — не выше сервиса.
- Между модулями (`auth`, `content`, `characters`, `campaigns`, `merchants`) — только вызовы чужих сервисов. Импорт чужих models — запрещён.
- Правила D&D 5e — только в `app/characters/rules_5e.py`, чистыми функциями без I/O. Дублировать формулы в других местах нельзя.
- Типизация обязательна (mypy-дружелюбно); Pydantic v2; async SQLAlchemy 2 style (select(), не query()).
- Ошибки — доменные исключения модуля, маппятся в `{error:{code,message}}` централизованно. Не поднимать HTTPException из сервисов.
- Деньги: три integer-поля gold/silver/copper, никакой конвертации, никаких float.
- Простое лучше абстрактного: не вводить интерфейсы/фабрики/паттерны «на будущее». SOLID применяется как здравый смысл (одна ответственность, зависимость от абстракций в сервисах), а не как повод плодить слои.

## TypeScript (frontend)
- Функциональные компоненты; состояние сервера — только TanStack Query (не useEffect+fetch); формы — react-hook-form + zod.
- Никаких русских строк в JSX — только ключи i18next.
- API-вызовы — через общий клиент из `frontend/src/api/`; типы ответов зеркалят Pydantic-схемы.
- Правила 5e на фронте не считать — использовать блок `computed` из API.

## Тесты
- Каждый критерий приёмки задачи → минимум один тест, названный по смыслу критерия.
- Тесты прав доступа (чужой ресурс) обязательны для каждого нового эндпоинта.
- Не мокать БД в интеграционных тестах — тестовая Postgres из CI.

## Коммиты
- Английский, imperative: `add merchant buy endpoint`, `fix rollback delta for spells`.
- Один коммит — одно логическое изменение.
